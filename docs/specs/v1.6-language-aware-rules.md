# Language-Aware Rule Matching via Glob-Gated Coding Standards

> Release: **v1.6** · Label: `enhancement`
> ADR: [0010](../adr/0010-dual-key-coding-standards.md)

## Summary

Extend coding standards injection to accept an array of glob-matched rule files (`review.codingStandards`) alongside the existing single-file `review.codingStandardsPath`. Only inject rules relevant to each file type in the prompt.

**Inspired by:** Alibaba open-code-review's `system_rules.json` template engine that maps 40+ language-specific rule documents.

## Why

Current single `codingStandardsPath` sends the same rules for all file types. This causes irrelevant findings and wasted prompt tokens in polyglot repos.

## Config shape

```yaml
review:
  # Legacy single-file (still works, also the learn read/write target):
  codingStandardsPath: rules/general.md

  # New per-language array:
  codingStandards:
    - glob: "*.java"
      path: rules/java.md
    - glob: "*.ts"
      path: rules/typescript.md
    - glob: "*.py"
      path: rules/python.md
```

### Backward compatibility

- Plain string `codingStandardsPath` still works — auto-wraps to `[{ glob: "*", path: value }]` internally.
- Both keys set → `codingStandardsPath` is prepended as `{ glob: "*", path }` catch-all to the array. Deduplicated by resolved absolute path.
- Array-only (no `codingStandardsPath`) → review works; learn/suppression are unavailable.

### Validation

- Array entries must have `{ glob: string, path: string }` — malformed entries raise `ConfigError` (fail fast).
- Normalization happens in `config-loader.js` at validation time → downstream code sees `config.review._codingStandards: Array<{ glob, path }>`.

## Matching behavior

- **Library**: `minimatch` v10 (already installed).
- **Options**: `{ matchBase: true }` — `*.ts` matches `src/deep/foo.ts` (matches basename when pattern has no slashes).
- **Semantics**: All-match union — a file gets rules from every matching glob, not just the first.
- **Concatenation order**: Array order as declared in config. General rules first, specific overrides last.
- **No-match fallback**: Files matching zero globs get the existing fallback text (`"(No project coding standards configured. Apply language-idiomatic best practices.)"`).
- **Deduplication**: By resolved absolute path — same file injected only once even if matched by multiple globs.

## Matching granularity

Per-call union: collect all globs that match any file in the LLM call batch, concatenate their contents, inject once into the system prompt. No multi-call split.

## Learn pipeline

- `codingStandardsPath` remains the exclusive learn read/write target ([ADR-0010](../adr/0010-dual-key-coding-standards.md)).
- Suppression rules (`extractSuppressionRules`) extracted from `codingStandardsPath` only. Empty when unset.
- Learn requires `codingStandardsPath` to be set — existing `ConfigError` validation unchanged.

## Reply path

Reply uses `codingStandardsPath` content only (catch-all). No glob matching in the reply path — reply already has rich per-thread context.

## Token budget

No new guard. `buildPrompt` already subtracts system-prompt tokens from the file-diff budget. Larger standards = fewer file diffs included — self-regulating.

## Files

| File | Change |
|---|---|
| `lib/config-loader.js` | Validate `codingStandards` array, normalize to `_codingStandards` |
| `lib/context-loader.js` | New `loadCodingStandardsArray(cwd, entries)` + `matchStandardsForFiles(entries, filePaths)` |
| `ai-review.js` | Call `loadCodingStandardsArray` + `matchStandardsForFiles`, pass concatenated string to `buildPrompt` |
| `docs/config.md` | Document new `codingStandards` key |
| `docs/adr/0010-dual-key-coding-standards.md` | Dual-key design rationale |
| Tests | `context-loader.test.js` (new), `config-loader.test.js` updates |

## Non-goals

- Per-file prompt splitting (separate LLM calls per language) — future if needed.
- Glob matching in the reply path.
- Token budget warnings for large rule sets.
