# Reflection Filter — Second-Pass LLM Validation

> Release: **v1.5** · Label: `enhancement`

## Summary

After the review LLM returns findings, run a second-pass validation using the reply model (Haiku) to check each finding: "Is this actually valid and actionable given the code context?" Drop false positives before posting.

**Inspired by:** Alibaba open-code-review's reflection module.

## Why

False positives are the #1 quality gap. Current pipeline posts everything the LLM returns after basic validation. A reflection step would catch:
- LLM hallucinating code behavior that doesn't exist
- Findings that are technically correct but not actionable
- Findings that don't understand the project's patterns

## Design Decisions

- **Config:** `review.reflection` (boolean, default `true`)
- **Model:** uses `reply.provider` / `reply.model` (Haiku by default)
- **Cost:** ~$2-5/month additional for a 10-engineer team
- **Pipeline position:** after `validateFindings` + `shouldDropAsNoise`, before `reconcilePort`
