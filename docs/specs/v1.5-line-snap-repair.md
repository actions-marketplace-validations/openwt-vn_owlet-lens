# Line-Number Snap Repair

> Release: **v1.5** · Label: `enhancement`

## Summary

Instead of dropping findings with slightly-off line numbers, snap them to the nearest valid diff line within a ±5 line window. Only drop if no valid line exists nearby.

**Inspired by:** Alibaba open-code-review's `comment_args_repair.go` positioning module.

## Why

The LLM sometimes returns findings with line numbers off by a few lines (e.g. says line 42, actual change is at line 44). Currently `finding-validator.js` drops these as invalid. Snapping to the nearest valid line recovers directionally-correct findings.

## Design

- Check if finding's line is within the diff's changed lines
- If not, search ±5 lines for the nearest valid diff line
- If found, update the line number; if not, drop as before
- Window size could be configurable but ±5 is a sensible default
